# AGENTS.md — Rules for AI Agents Working on NFAI Labs

These rules apply to every AI coding agent or assistant working in this repository. They override convenience. When in doubt, stop and ask the owner.

**Owner:** Nicolas Familia (GitHub `NickyBFam`)
**Current approved phase:** Phase 1 — Application Foundation (approved to begin 2026-09-29; awaiting owner review, not yet complete). Phase 0 is approved and closed. The authoritative status is in `docs/PHASES.md`.
**Canonical branch:** `main` (configured by the owner; see `docs/DECISIONS.md` D-017)
**License:** All rights reserved (D-018)

## Read first

Before doing any work, read:
1. `docs/PHASES.md` — which phase is approved and what is in and out of scope.
2. `docs/MASTER_SPEC.md` — what the product is.
3. `docs/DECISIONS.md` — what has already been decided and what is open.
4. `docs/METHODOLOGY.md` and `docs/DATA_SOURCES.md` — before touching any data, benchmark, or ranking logic.
5. `docs/ARCHITECTURE.md` — before making structural or technology choices.

## Phase discipline

1. **Work only on the currently approved phase.** The approved phase is stated at the top of `docs/PHASES.md`.
2. **Do not silently expand scope.** If a task seems to require work from another phase, stop and report it instead of doing it.
3. **Do not begin the next phase** until the owner explicitly approves the current phase's completion gate.
4. **End each phase with the structured report**: PHASE, STATUS, REPOSITORY OBSERVED, FILES CREATED, FILES MODIFIED, KEY DECISIONS, OPEN QUESTIONS, VALIDATION PERFORMED, GIT STATUS, NEXT PHASE.

## Data integrity

5. **Do not invent production data.** No made-up providers, models, versions, dates, or records presented as real.
6. **Do not fabricate benchmark results.** Never estimate, interpolate, or "fill in" scores.
7. **Do not fabricate pricing or model capabilities.** Unknown values stay unknown.
8. **Cite or record sources for externally sourced factual data**, following `docs/DATA_SOURCES.md` (source URL, publisher, tier, dates).
9. **Attach results to the exact model/version and configuration**, never to a provider or model family.
10. **Never silently mix results** obtained under materially different evaluation conditions (`docs/METHODOLOGY.md` §6).
11. **Test fixtures must be obviously synthetic** and must never be seeded into production or displayed as real data.
12. **Store structured facts, summaries, provenance, and links** — never copy articles, docs, datasets, or leaderboards wholesale.

## History and baselines

13. **Preserve historical data.** Do not overwrite or delete pricing, results, capabilities, rankings, or methodology history; supersede with new records.
14. **Do not modify previous baselines casually.** Approved methodology versions, ranking snapshots, schemas, and evaluation environments change only through a recorded decision.

## Quality

15. **Tests must accompany future production logic where appropriate** — especially data validation, comparability rules, ranking math, pricing calculations, ingestion parsing, and access control.
16. **Keep CI green** (from Phase 1 onward). Do not disable or weaken tests to make them pass.
17. **Update documentation** when behavior or decisions change.

## Decisions

18. **Document unresolved decisions instead of guessing.** Add an `Open` entry to `docs/DECISIONS.md` and raise it in the phase report.
19. **Do not silently make major product or architecture decisions.** If the planned stack has a serious problem, record it in `docs/DECISIONS.md` rather than changing it.

## Git and attribution (strict)

20. **Do not create Git commits.** Do not run `git commit` or equivalents.
21. **Do not push.** Do not run `git push` or equivalents.
22. **Do not create pull requests** (`gh pr create` or any GitHub-writing command).
23. **Do not change Git configuration**, including `user.name` and `user.email`, and do not add or change remotes.
24. Read-only Git inspection (`git status`, `git log`, `git diff`, `git ls-remote`) is allowed.
25. **No AI attribution anywhere**: no `Co-authored-by` trailers for any AI, no "Generated by/with" lines, and no AI or vendor authorship notes in files, commit messages, PR descriptions, or metadata. The owner performs all commits and pushes personally.

## Safety

26. Never commit or write secrets, API keys, or credentials into the repository.
27. Do not install dependencies or run network-writing operations outside the approved phase's scope.

## Licensing and commercial independence

28. **Do not add a license.** The project is all rights reserved (D-018). Do not add `LICENSE` files, license headers, or open-source/open-data terms unless the owner explicitly approves one.
29. **Commercial relationships never influence data.** Sponsorship, affiliate, payment, or partnership data must never affect benchmark results, rankings, derived scores, methodology, or recommendations. Any sponsored or affiliate content must be clearly disclosed and structurally separated (D-015).

## Working in the application (Phase 1 onward)

30. Use npm. Run `npm run validate` (lint, format check, typecheck, tests, build) before reporting work as complete.
31. Keep `src/lib/product-areas.ts` structural only: descriptions and phase references, never models, providers, prices, scores, or rankings.
32. Prefer Server Components; add `"use client"` only where interactivity requires it.
33. Pin dependency versions exactly and record significant tooling choices in `docs/DECISIONS.md`.
34. Next.js 16 differs from older versions. Read the bundled docs in `node_modules/next/dist/docs/` before using a Next.js API.
